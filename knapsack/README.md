# Решение 2

Метод ветвей и границ с несколькими эвристиками:
- На каждой итерации считается оценка сверху - решение релаксации (непрерывный рюкзак), и оценка снизу - жадное решение, на не рассмотренных переменных. Максимальный ответ сразу релаксируется оценкой снизу, отсечение происходит если оценка сверху меньше чем максимальный ответ.
- Перед запуском рекурсии сортируем элементы по убыванию cost / weight. Во-первых, чтобы не пересортировывать их при подсчете оценок, во-вторых, потому что, кажется, в таком порядке перебор работает лучше, потому что если не выбрать какой-то из ранних элементов, то жадник может сработать сильно лучше.
- При ветвлении предпочитаем ветку с бОльшим lower bound, чтобы сразу как можно сильнее его завысить и потом больше отсекать.

Оно очень хорошо сработало: пробило все верхние пороги. Более того, я поставил MAX_STEPS = 300000, но на всех тестах оно сошлось быстрее. То есть по факту просмотрело все ветки. Можно ли считать это доказательством оптимальности решения? (в этом можно убедиться, пересобрав с флагом -DCMAKE_BUILD_TYPE=DEBUG и посмотрев на прогресс бар который останавливается раньше 30000).
